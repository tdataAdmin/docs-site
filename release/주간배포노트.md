## 2026-10-03 — `설정.json` → TOML 변환 (경로·일정 유지 확인)

`설정.json`을 TOML로 변환했습니다. **요구사항에 따라 입력/출력 경로와 파이프라인 일정(cron)은 원본 값을 그대로 유지**했으며, 값 변경은 없습니다. (작업 기준 2026-10-03, KST)

### 변환 대상과 결과

| 항목 | 값 |
| --- | --- |
| 원본 (JSON) | `자료/설정.json` |
| 결과 (TOML) | `산출/설정.toml` |
| 변환 방향 | `json_to_toml` |
| 결과 파일 크기 | 758 bytes |
| 변환 시각 (KST) | 2026-10-03 20:31 |
| 경로·일정 값 변경 여부 | **없음 (원본 유지)** |

### 경로·일정 원본 대조

| 항목 | JSON 원본 | TOML 변환 후 | 키 경로 | 유지 |
| --- | --- | --- | --- | --- |
| 입력 경로 | `자료/매출.csv` | `자료/매출.csv` | `pipeline.input.path` | ✅ |
| 출력 경로 | `리포트/매출_주간.json` | `리포트/매출_주간.json` | `pipeline.output.path` | ✅ |
| 파이프라인 일정 | `0 6 * * 1` | `0 6 * * 1` | `pipeline.schedule` | ✅ |
| 입력 인코딩 | `utf-8` | `utf-8` | `pipeline.input.encoding` | ✅ |

- 일정 `0 6 * * 1`(cron 5필드)은 **매주 월요일 06:00** 실행을 의미합니다. 문자열 그대로 보존되어 실행 시점이 동일합니다.
- 경로는 상대 경로 표기(`자료/…`, `리포트/…`)와 한글 디렉터리명, 언더스코어(`매출_주간`)까지 그대로 유지되었습니다. 확장자(`.csv`, `.json`)도 변경 없습니다.

### 변환된 TOML 전문

```toml
[service]
name = "fixture-service"

[service.settings]
timeout_sec = 30
retry = 3
debug = false

[[endpoints]]
name = "primary"
url = "https://api.example.co.kr/v1"

[[endpoints]]
name = "backup"
url = "https://api-backup.example.co.kr/v1"

[pipeline]
schedule = "0 6 * * 1"

[pipeline.input]
path = "자료/매출.csv"
encoding = "utf-8"

[pipeline.input.schema]

[[pipeline.input.schema.columns]]
name = "date"
type = "date"
required = true

[[pipeline.input.schema.columns]]
name = "product_name"
type = "string"
required = true

[[pipeline.input.schema.columns]]
name = "quantity"
type = "integer"
required = true

[[pipeline.input.schema.columns]]
name = "amount"
type = "number"
required = true

[pipeline.output]
path = "리포트/매출_주간.json"
```

### 참고 사항

- JSON의 `endpoints` 배열과 `pipeline.input.schema.columns` 배열은 TOML 배열 테이블(`[[…]]`)로 변환되었습니다. **요소 순서와 개수(endpoints 2건, columns 4건) 및 `required` 값은 원본과 동일**합니다.
- 타입 보존: 숫자(`timeout_sec=30`, `retry=3`), 불리언(`debug=false`), 문자열 모두 원본 리터럴 그대로이며 값의 재해석은 없습니다.
- 변환된 TOML은 로컬 산출물(`산출/설정.toml`)에만 존재하며, **이 저장소에는 아직 커밋되지 않았습니다.** 실제 파이프라인에서 TOML을 로드하려면 파일 배치 후 `pipeline.input.path` / `pipeline.output.path` 기준 상대 경로가 실행 환경의 작업 디렉터리 기준으로 유효한지 별도로 확인이 필요합니다.
- 아래 2026-10-03 주차 유의사항에서 확인된 대로 `매출.csv` 스키마(12열 확장)와 이 설정의 `columns` 4열 정의는 **서로 일치하지 않습니다.** TOML 변환과는 무관한 기존 미해결 사항이며, 파이프라인 재실행 전 반드시 함께 점검해 주세요.

### 확인 결과 — 매출 CSV 스키마 변경 안내 누락

`매출.csv` 스키마 변경 안내는 ① GitHub 릴리스 본문, ② 같은 디렉터리의 [릴리스노트.md](./%EB%A6%B4%EB%A6%AC%EC%8A%A4%EB%85%B8%ED%8A%B8.md), ③ 위 `data-pipeline` 커밋 내역 **세 곳 모두에서 확인되지 않습니다.** 릴리스노트.md는 `설정.json` 필드 타입/필수 여부만 다룹니다.

한편 실제 `매출.csv`(44행, UTF-8 BOM)는 열이 12개로 확장된 상태여서, 변경이 발생했는데도 문서에 반영되지 않은 것으로 보입니다.

- 기존 집계 열 4종: `월`, `지역`, `매출`, `건수`
- 신규 거래 단위 열 8종: `판매일(sale_date)`, `주문번호(order_id)`, `상품코드(product_code)`, `상품명(product_name)`, `판매금액(amount)`, `결제수단(payment_method)`, `통화코드(currency)`, `갱신시각(updated_at)`
- 두 스키마가 한 파일에 혼재: 기존 집계 행(20행)은 신규 8종이 전부 비어 있고, 2026-06 거래 행(24행)은 기존 `매출`·`건수`가 비어 있음
- 동반된 데이터 품질 이슈: `판매금액`에 `1,500원` · `금액미정` · `abc123` 등 비숫자 값 혼입, 쉼표 미인용(`무선 이어폰, 충전기 세트`)에 따른 열 밀림, `주문번호`·`상품코드` 결측, `통화코드`에 KRW 외 USD/JPY/EUR 혼재, 일부 행 말미 여분 쉼표

**조치 필요:** 공지 문구("이번 주 매출 CSV 스키마 변경 반영")의 근거를 릴리스 어디에서도 찾을 수 없습니다. 릴리스 본문 또는 릴리스노트.md에 매출 CSV 변경 이력 섹션(추가 열 8종, 혼재 구간, 클리닝 규칙)을 추가해야 합니다.
